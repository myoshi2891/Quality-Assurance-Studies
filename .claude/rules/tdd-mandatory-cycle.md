# TDD 必須サイクル & コミット分割ルール

プロジェクトの品質とトレーサビリティを担保するため、以下の TDD サイクルおよびコミット分割を**絶対的な強制ルール**として適用する。

## 核心原則

<ai_agent_directive>
**AI エージェントへの厳格な指示**:

1. **Red（テスト失敗）フェーズを経ないコード実装は「未完了」とみなす。** 実装コードを書く前に、必ず失敗するテストをコミットすること。
2. **一括コミットの禁止。** 「テスト + 実装 + ドキュメント」を一つのコミットにまとめることは重大な規約違反である。
3. **違反検知時は即時報告。** サイクルを飛ばしたことに気づいた場合、独断で `git reset` 等を実行せず、直ちにユーザーへ報告し、承認を得たうえでリカバリ手順を実施すること（詳細は「違反時の対応」を参照）。
</ai_agent_directive>

## 全コミット共通の必須検証（PII スキャン）

Red / Green / Refactor / Docs Sync のいずれのコミットであっても、`git commit` の直前に必ず以下を実行する。
検出時は終了コード 1 で失敗させ、コミットを中止すること（走査本体は `.claude/rules/no-absolute-paths.md` の正本と同一。grep パターン自身が自己一致しないよう文字クラスで 1 文字を分割している）。

```bash
# >>> pii-scan
# 各段階の失敗を「該当なし」と区別する: git / awk の失敗は pipefail で検出し、grep は 1（該当なし）のみを正常とみなす
# --text でバイナリ扱いのファイルも中身を差分に含め、NUL は空白に置き換えて awk が行を途中で打ち切らないようにする（走査から漏らさない）
if ! added=$(set -o pipefail; git diff --cached --text | tr '\000' ' ' | awk '/^diff --/{h=1; next} /^@@/{h=0; next} h{next} /^\+/{print substr($0, 2)}'); then
  echo "diff extraction failed — abort commit" >&2
  exit 1
fi
# grep を if の条件に置き、errexit（set -e）下でも終了ステータスを記録する前にシェルが終了しないようにする
# pipefail で grep の失敗を sed の終了ステータスに隠さず、下の rc 判定へ渡す
# file:// URI は境界の文字クラスを緩めず接頭辞として許可し（https URL のパス部分は対象外のまま）、sed で先頭を単一の / に揃えてプレースホルダー判定へ渡す
# Windows の file:// URI はドライブ文字の前に / が付いた形へ揃うため、プレースホルダー判定でもその形を認める
# 別のパス要素より下にあるユーザーディレクトリ（WSL のドライブマウントや外部ボリューム配下など）も検出する。起点は境界の直後に限り、途中の要素は空にできないため、URL のパス部分と相対パスは対象外のまま
# opt / srv / workspace は Homebrew の共有ディレクトリなどを誤検出しないよう、ルート直下だけを対象にする
# Windows のドライブは C: に限らず、大文字・小文字の全ドライブ文字を検出する。ドライブ文字で始まる一致を消さないよう、sed は境界の 1 文字と file:// だけを外す
# UNC パスも Windows のドライブと同じ規則で検出する（サーバー名と共有名は途中の要素として扱う）
# 空白を含むパス要素も検出する。空白は要素の内側だけに許可し、2 語目以降は ":" を含められない（同じ行の別のドライブや URL スキームまで 1 要素にしないため）。区切り文字が続かない語は末尾の文章とみなして取り込まない
seg='[^/[:space:]"'\''`<>]+( +[^/:[:space:]"'\''`<>]+)*'
win='[^\\[:space:]"'\''`<>]+( +[^\\:[:space:]"'\''`<>]+)*'
word='[^/\\:[:space:]"'\''`<>]+'
# file:// URI 内のパーセントエンコードされた保護ディレクトリ名（先頭文字を含む）も検出する
usr='(U|%55)(s|%73)(e|%65)(r|%72)(s|%73)'
hm='(h|%68)(o|%[6][fF])(m|%[6][dD])(e|%65)'
# %2F・%5C でエンコードされた区切り文字は抽出前に復号する（URL のパス部分は境界の判定により対象外のまま）
if paths=$(set -o pipefail; printf '%s\n' "$added" | sed -E -e 's#%2[fF]#/#g' -e 's#%5[cC]#\\#g' | grep -oE '((^|[^A-Za-z0-9._~/-])(file://(localhost)?)?/(('"$seg"'/)*('"$usr"'|'"$hm"')|op[t]|sr[v]|workspac[e])/|[A-Za-z]:\\('"$win"'\\)*[Uu][Ss][Ee][Rr][Ss]\\|\\\\[^\\[:space:]]+\\('"$win"'\\)*[Uu][Ss][Ee][Rr][Ss]\\)[^[:space:]"'\''`]*( +('"$word"' +)*'"$word"'[/\\][^[:space:]"'\''`]*)*' | sed -E -e 's#^[^/A-Za-z]*##' -e 's#^file://(localhost)?##'); then
  rc=0
else
  rc=$?
fi
if [ "$rc" -gt 1 ]; then
  echo "grep failed (exit $rc) — abort commit" >&2
  exit 1
fi
if [ "$rc" -eq 0 ]; then
  # %XX は 1 回だけ復号し、".."・保護ディレクトリ・プレースホルダーの判定をすべて復号後の値で行う（検出時は元の表記を表示する）
  # 16 進数の変換は macOS awk / mawk でも動くよう index() で行い、制御文字と非 ASCII は復号しない
  # プレースホルダーとして除外するのは、保護ディレクトリがパス全体で 1 つだけで、その直下が johndoe のものに限る（途中の要素に別のユーザーディレクトリがあれば除外しない。opt / srv / workspace はルート直下の要素がユーザー名の場合があるため、配下のプレースホルダーも除外しない）
  if ! hits=$(printf '%s\n' "$paths" | awk '
         function decode(s, out, h, c) {
           out = ""
           while (match(s, /%[0-9A-Fa-f][0-9A-Fa-f]/)) {
             h = tolower(substr(s, RSTART + 1, 2))
             c = (index("0123456789abcdef", substr(h, 1, 1)) - 1) * 16 + index("0123456789abcdef", substr(h, 2, 1)) - 1
             out = out substr(s, 1, RSTART - 1) (c >= 32 && c < 127 ? sprintf("%c", c) : substr(s, RSTART, 3))
             s = substr(s, RSTART + RLENGTH)
           }
           return out s
         }
         {
           d = decode($0); gsub(/\\/, "/", d); n = split(d, part, "/"); count = 0; first = 0
           if (d ~ /^\/(op[t]|sr[v]|workspac[e])\//) { print; next }
           for (i = 1; i <= n; i++) {
             if (part[i] == "..") { print; next }
             if (tolower(part[i]) ~ /^(user[s]|hom[e])$/) { count++; if (first == 0) first = i }
           }
           if (count != 1 || part[first + 1] != "johndoe") print
         }
         '); then
    echo "placeholder filter failed — abort commit" >&2
    exit 1
  fi
  if [ -n "$hits" ]; then
    printf '%s\n' "$hits"
    echo "PII detected — abort commit" >&2
    exit 1
  fi
fi
echo "PII check passed"
# <<< pii-scan
```

検出された場合は該当箇所を相対パスへ書き換えるか削除し、クリーンであることを再確認したうえでコミットする。

## 必須ワークフロー

### ステップ 1: Red（テストの作成と失敗）

作業種別に応じて以下を選択する:

- **HTML 移行の場合**: 移行着手前に元 HTML の全構成要素（全見出し、全 TOC リンク、全 Mermaid 図解、全表、全コードブロック、全コールアウト、全参考文献）の棚卸しインベントリを作成する。そして、これらの構成要素がすべて正しくレンダリングされていることを 1 対 1 でアサーションする網羅的テストファイルを `tests/` 下に作成する（抜け漏れゼロの担保）。アサーションは件数の下限確認ではなく、出現順の固定配列との 1 対 1 照合とし、欠落と余剰の両方を検出できる形にする。
- **新機能の場合**: 元 HTML を前提にしない。実装しようとしている振る舞い（入力・操作に対する期待出力、DOM 構造、アクセシビリティ属性の遷移など）を記述した失敗テストを先に作成する。既存 HTML のインベントリ照合は行わない。
- **バグ修正の場合**: 現在の不具合を再現する失敗テストを追加する。テストがパスしてしまう場合は再現条件を見直す。
- **機能改善の場合**: 期待する新しい振る舞いを記述した失敗テストを追加する。
- **リファクタリングのみの場合**: 既存テストをそのまま実行してすべてパスすることを確認する。新規テストの作成は不要。

- **実行**: `bun test`で失敗（またはコンパイルエラー）を確認する（リファクタリングはパスを確認）。
- **コミット前必須検証**: 「全コミット共通の必須検証」の PII スキャンを実行する。
- **コミット（新機能・バグ修正・機能改善時）**: `test(<scope>): add failing spec for <feature-or-bug-id>`

### ステップ 2: Green（最小実装と成功）

- テストをパスさせるための最小限のコードを `app/` または `components/` 等に実装。
- **実行**: `bun test`でパスを確認。
- **コミット前必須検証**: 「全コミット共通の必須検証」の PII スキャンを実行する。
- **コミット**: `feat(<scope>): <feature implementation summary>`

### ステップ 3: Refactor（リファクタリング・最適化）

- コードの重複削除、読みやすさの向上、リンターエラーの修正。
- **重要（サンドボックス環境のビルド制約）**: Antigravityのサンドボックス環境においては、ビルドのバックグラウンド実行が正常にハンドリングされずローカルメモリを過度に圧迫しクラッシュを引き起こす問題があるため、AIエージェントは自律的・自動的に本番ビルドコマンド（`bun run build` 等）を実行してはならない。検証はテストおよび `bun run lint`で行い、本番ビルドの確認はユーザーへ依頼すること。
- **コミット前必須検証 (PII スキャン)**: 「全コミット共通の必須検証」を実行し、パスすることを確認する。
- **コミット**: `refactor(<scope>): <clean up or optimization>`

### ステップ 4: Docs Sync（進捗同期）

- 作業対象が HTML → Next.js ページ移行タスク（`app/` 下のページ新規作成・移行）の場合のみ `docs/MIGRATION_PROGRESS.md` を更新する。判定基準：
  - HTMLコンテンツをReactコンポーネントへ変換
  - 既存ページのルーティング・ビジネスロジックをNext.js構成に合わせて変更
  - 移行に伴うスタイル調整やアセットパス修正
  - 新規 page.tsx 作成に伴う既存 page の削除/置換
  など、`app/**/page.tsx` の新規作成または明確な移行に伴う編集が含まれる場合に適用。バグ修正・スタイル微調整・ユーティリティの独立変更などは除外。
- **コミット前必須検証**: 「全コミット共通の必須検証」の PII スキャンを実行する。
- **コミット（移行タスク時のみ）**: `chore(docs): update docs/MIGRATION_PROGRESS.md — <page/feature name>`

## 除外事項

- 既存ファイルの誤字修正や、コードロジックに影響しないコメントの微修正のみ。
- ただし、ロジックに変更が生じた場合は、必ず既存のテストを更新または新しいテストを追加すること。

## 違反時の対応

万が一、このルールに違反（手順のスキップや一括コミットなど）したことに気づいた場合は、以下の手順を徹底すること：

1. **即座に報告**: ユーザーに対して、どの手順をスキップしたか、どのコミットが不適切であったかを直ちに報告する。
2. **勝手な修復の禁止**: ユーザーの承認を得る前に `git reset` や修正コミットを自律的に実行してはならない。
3. **リカバリ案の提示**: 正しい状態に戻すための手順（例：直近のコミットの取り消しと再実行）を提案し、承認を得てから実行する。
