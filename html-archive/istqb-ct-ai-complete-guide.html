Chapter 01 K1/K2

AIの概要（Introduction to AI）

学習目標： AIの定義・種類・主要技術を認識し、従来型システムとの違いを説明できる。

1.1 AIとは何か — 定義とAI効果

定義（ISO）
「知識とスキルを獲得・処理・適用するエンジニアリングシステムの能力」— ISO/IEC JTC 1/SC 42
AI効果
AIが何かを達成すると「それは本物のAIではない」と思われる社会的現象。AIの定義は時代とともに変化する。
💡 AI効果の具体例
Deep Blue がチェスで人間を倒した後、「ブルートフォースなので真のAIではない」と批判された。しかし当時は「チェスを指せるAI」こそが夢だった。今日の「AI」も10年後は当たり前の技術になる。

1.2 狭義AI / 汎用AI / 超AI（試験頻出）

種類 別名 特徴 現状
狭義AI（Narrow AI） 弱いAI 特定タスクに特化・文脈が限定的 ✅ 広く普及
汎用AI（General AI） 強いAI 人間同様の汎用認知・理解・推論・適応 ❌ 未実現
超AI（Super AI） Super AI 人間を超える認知能力・技術的特異点の先 ❌ 未実現

1.3 AIベースシステム vs 従来型システム（試験頻出）

✅ 従来型システム

人間がルール（if-then-else）をコーディング。決定論的（同じ入力→同じ出力）。ロジックが追えるので説明可能性が高い。テスト設計が明確。

⚠️ AIベースシステム（テストの難しさ）

データからパターンを学習。確率論的（同じ入力≠同じ出力）。ブラックボックスになりがち。テストオラクル問題・非決定論的動作が課題。

1.4 主要なAI技術（K1 — 認識レベル）

ファジーロジック
「あいまいな」値を扱う論理。真偽の2値ではなく連続値で表現
検索アルゴリズム
A* 探索・最適化問題の解法
推論技術
ルールエンジン・事例ベース推論
機械学習技術
ニューラルネット・決定木・ランダムフォレスト・SVM・ベイジアンモデル・遺伝的アルゴリズム

フレームワーク 提供元 主な特徴

フレームワークの実装詳細は不要。「名称を見て何のフレームワークか認識できる」K1レベルで十分。

1.7 AIaaS と転移学習のテストリスク

Chapter 02 K2

AIベースシステムの品質特性

学習目標： AI固有の品質課題（バイアス・倫理・XAI等）を説明できる。

AI固有の品質特性マップ

柔軟性・適応性
異なる環境・データ分布に対応・学習・調整できる能力
自律性
外部の直接的な制御なしに機能を実行できる能力（自動運転 Level 0〜5）
進化性
継続的な学習による性能変化・予期しない挙動変化のリスク
バイアス
アルゴリズム / サンプル / 不適切バイアスの3種（後述）
倫理・安全性
公平性・透明性・プライバシー・アカウンタビリティ・非差別
副作用・報酬ハッキング
目標達成のために予期しない負の影響（副作用）や抜け穴悪用（報酬ハッキング）

2.4 バイアスの3種類（試験頻出）

バイアスの種類 定義 具体例
アルゴリズムバイアス アルゴリズム自体に内在する偏り 特定人種に不利な採用AIのロジック
サンプルバイアス トレーニングデータが実際の分布を反映していない 白人男性の顔画像のみで学習した顔認識システム
不適切バイアス 差別や不公平を生む偏り 性別・人種・年齢で差別するローン審査AI

2.7 透明性・解釈可能性・説明可能性（XAI）の違い（試験頻出）

透明性（Transparency）
AIシステムの動作に関する情報を公開する度合い。「どんなデータで学習したか」「どんなアルゴリズムを使ったか」
解釈可能性（Interpretability）
人間がAIの内部動作を理解できる度合い。「モデルがどのように予測を出しているか理解できる」
説明可能性（Explainability / XAI）
特定の予測・決定の根拠を説明できる能力。「この診断の根拠は〇〇という特徴量の影響」。ツール：LIME・SHAP・Grad-CAM
💡 医療AIの例で理解する
透明性：「X線画像8万枚で学習したCNNモデル」（公開情報）
解釈可能性：「肺の特定領域の輝度パターンで判断」（内部動作の理解）
説明可能性：「この画像は右上肺野の輝度が通常より20%高いため異常と判定」（個別予測の根拠）

2.6 副作用と報酬ハッキング

❌ 副作用（Side Effects）の例

ロボットが「部屋を片付ける」タスクで、物を隠蔽・破壊することで達成しようとする。目標は達成するが意図しない被害が出る。

❌ 報酬ハッキング（Reward Hacking）の例

ゲームAIが「スコアを最大化」するために、チートに相当する方法（ゲームのバグ悪用等）でスコアを稼ぐ。報酬関数の「抜け穴」を悪用。

Chapter 03 K2/K3

機械学習（ML）概要

学習目標： 教師あり・なし・強化学習を区別し、MLワークフローとオーバーフィッティングを説明できる。

3.1 機械学習の3形態（試験頻出）

形態 データ タスク例 ユースケース
教師あり学習 ラベル付きデータ 分類・回帰 スパムフィルター・医療診断・画像分類
教師なし学習 ラベルなしデータ クラスタリング・次元削減 顧客セグメンテーション・異常検知・推薦
強化学習 環境との試行錯誤 報酬最大化 AlphaGo・ロボット制御・自動運転

3.2 MLワークフロー（試験頻出）

  1. 1問題定義：解くべきビジネス課題を明確にする
  2. 2データ収集：様々なソースからバイアスなく収集
  3. 3データ準備 ← テスターの重要な関与点：欠損値・外れ値・重複・プライバシー対応
  4. 4特徴量エンジニアリング：モデルへの入力を最適化
  5. 5アルゴリズム選択：問題特性に合ったモデルを選ぶ
  6. 6モデルトレーニング：トレーニングデータで学習
  7. 7モデル評価 ← テスターの重要な関与点：精度・バイアス・公平性の検証
  8. 8ハイパーパラメータ調整：バリデーションデータで最適化
  9. 9モデルデプロイ：本番環境への展開
  10. 10モニタリング ← コンセプトドリフト監視が継続的に必要

3.5 過学習と未学習（試験頻出）

❌ 過学習（Overfitting）

トレーニングデータに過剰適合。訓練精度：99%、バリデーション精度：65%のように乖離が大きい。モデルが複雑すぎ・データが少なすぎ・ノイズまで学習。

❌ 未学習（Underfitting）

データのパターンを十分学習できていない。訓練精度も低い（65%程度）。モデルが単純すぎ・学習不足・特徴量不足。

✅ 理想：訓練精度もバリデーション精度も高く、かつ近い値（例：92% vs 90%）。一般化誤差が小さい状態。
Chapter 04 K2/K3

ML データ（230分 — 重要章）

学習目標： データ品質問題を特定し、3種類のデータセットの役割を説明できる。

4.2 3種類のデータセット（試験頻出）

データセット 用途 目安比率 注意点
トレーニング（Training） モデルの学習・パラメータ調整 70〜80% 最も大きいデータセット
バリデーション（Validation） ハイパーパラメータ調整・モデル選択・過学習の早期検出 10〜15% 学習には使わない
テスト（Test） 最終性能評価（一度だけ使用） 10〜20% 絶対に学習に使わない！
⚠️ データ漏洩（Data Leakage）に要注意！
テストデータの情報がトレーニングに混入すると、評価結果が過度に楽観的になる。「タイムリーク」（未来の情報を使って学習）も典型的な漏洩パターン。

4.3 データセット品質の5大問題

① クラス不均衡
陽性1%・陰性99%のデータで「全て陰性」と予測するだけで正解率99%になる。精度指標のみでは品質が評価できない。
② データノイズ
測定誤差・ラベリングミスによるノイズ。モデルの学習を妨げ、偽の相関を学習してしまう。
③ コンセプトドリフト
本番データの分布がトレーニングデータと時間とともに乖離していく現象（Ch7で詳述）。
④ データ漏洩
テストデータ情報のトレーニングへの混入。過度に楽観的な評価結果をもたらす。
⑤ 代表性の欠如
特定グループが過小代表 → バイアスの原因。例：医療AIの学習データに高齢者が少ない。

4.5 データラベリングとテスターのQA活動

# テスターのデータラベリングQA活動 — 概念実装例 def check_label_quality(labeled_data: list) -> dict: """ ラベリング品質のQAチェック - 一致率（Inter-Annotator Agreement）確認 - ランダムサンプリングによる正確性検証 - ラベリングガイドラインの品質確認 """ sample_size = int(len(labeled_data) * 0.05) # 5%をサンプリング issues_found = [] for item in labeled_data[:sample_size]: if item["confidence"] < 0.7: # 低信頼度ラベルを検出 issues_found.append({ "id": item["id"], "issue": "低信頼度ラベル", "confidence": item["confidence"] }) return { "total_checked": sample_size, "issues_found": len(issues_found), "issue_rate": len(issues_found) / sample_size, "needs_relabeling": len(issues_found) / sample_size > 0.05 }
Chapter 05 K3 — 計算必須！

ML 機能パフォーマンスメトリクス

学習目標： 混同行列から精度・適合率・再現率・F1を計算し、ユースケースに適したメトリクスを選択できる。

5.1 混同行列（Confusion Matrix）— 試験頻出！

【予測値】
陽性（Positive） 陰性（Negative）
【実際値】 陽性（Positive） TP（真陽性）
正しく陽性と予測		 FN（偽陰性）
⚠️ 見逃し！危険
陰性（Negative） FP（偽陽性）
偽アラーム		 TN（真陰性）
正しく陰性と予測

5.2 主要メトリクスの計算式（必ず暗記）

# 混同行列から主要メトリクスを計算する — 試験の計算問題 # 医療診断AI例：TP=90, TN=820, FP=30, FN=10 TP, TN, FP, FN = 90, 820, 30, 10 # 1. 正解率（Accuracy）= (TP + TN) / 全体 accuracy = (TP + TN) / (TP + TN + FP + FN) # → 94.7% # 2. 適合率（Precision）= TP / (TP + FP) # 「陽性と言った時にどれだけ正しかったか」 precision = TP / (TP + FP) # → 75.0% # 3. 再現率（Recall / Sensitivity）= TP / (TP + FN) # 「実際の陽性をどれだけ見つけられたか」 recall = TP / (TP + FN) # → 90.0% # 4. F1スコア = 2 × (Precision × Recall) / (Precision + Recall) # 適合率と再現率の調和平均 f1 = 2 * (precision * recall) / (precision + recall) # → 81.8% # 5. 特異度（Specificity）= TN / (TN + FP) specificity = TN / (TN + FP) # → 96.5% print(f"正解率: {accuracy:.1%}") # 94.7% print(f"適合率: {precision:.1%}") # 75.0% print(f"再現率: {recall:.1%}") # 90.0% print(f"F1スコア: {f1:.1%}") # 81.8%

5.3 適合率 vs 再現率のトレードオフ（試験頻出）

優先メトリクス 使うべき場面 理由
再現率（Recall）重視 癌診断・セキュリティ侵害検出・緊急事態検出 見逃し（FN）のコストが非常に高い
適合率（Precision）重視 スパムフィルター・広告ターゲティング・詐欺検出 偽アラーム（FP）のコストが高い
F1スコア 両方が重要な場合のバランス指標 適合率と再現率の調和平均
⚠️ 正解率のパラドックス
クラス不均衡データ（99%陰性）で「全員陰性」と予測するだけで正解率99%になる。しかしこのモデルは役に立たない。必ず複数のメトリクスを組み合わせること。

その他のメトリクス一覧

タスク メトリクス 概要
回帰 MAE 平均絶対誤差（外れ値に強い）
回帰 MSE / RMSE 2乗誤差（外れ値に敏感）
回帰 R²（決定係数） モデルの説明力（0〜1）
分類 AUC-ROC 閾値に依存しない総合性能
クラスタリング シルエットスコア クラスターの凝集度・分離度

MLニューラルネットワークとテスト

学習目標： NNの基本構造を理解し、ニューロンカバレッジの概念を説明できる。

6.1 ニューラルネットワークの基本構造

コンポーネント 役割
ノード（ニューロン） 入力を受け取り変換して出力する計算単位
重み（Weights） 接続の強さ（学習によって調整される）
バイアス（Bias） 活性化のオフセット値
活性化関数 ReLU・Sigmoid・Tanh等（非線形変換）
CNN 画像認識に特化した畳み込みネットワーク
RNN 時系列データ・テキスト処理に特化
Transformer NLP・大規模言語モデル（GPT等）の基盤

6.2 ニューロンカバレッジ（従来のコードカバレッジとの違い）

従来型コードカバレッジ

if文・ループ等の構造的カバレッジ。行・分岐・条件のカバレッジを測定。明確なロジックフローが存在する前提。

⚠️ NNではコードカバレッジが意味をなさない

ニューロンカバレッジを使う：活性化されたニューロン数 ÷ 全ニューロン数。入力データの多様性を高めてカバレッジを向上させる。

Chapter 07 K2/K3

AIベースシステムテスト概要

学習目標： AIシステムの6テストレベル・オートメーションバイアス・コンセプトドリフトを説明できる。

7.2 AIシステムの6つのテストレベル（試験頻出）

① 入力データテスト
MLモデルへの入力データの品質確認。形式・範囲・欠損・偏りを検証。
② MLモデルテスト
モデルの精度・過学習・バイアス・公平性を評価。混同行列・精度・再現率等のメトリクス確認。
③ コンポーネントテスト
AIコンポーネント単体の機能確認。入出力インターフェースの検証。
④ コンポーネント統合テスト
AIコンポーネントと他コンポーネントの連携確認。インターフェース・データフローの検証。
⑤ システムテスト
システム全体の機能・性能・非機能特性の確認。E2Eシナリオでの動作確認。
⑥ 受入テスト
ユーザー・ステークホルダーによる承認。ビジネス要件・倫理要件への準拠確認。

7.4 オートメーションバイアス（Automation Bias）

⚠️ オートメーションバイアスとは
人間がAIの出力を過度に信頼・依存する傾向。AIが間違っているときでも人間が批判的判断を失う。
例：医師がAI診断ツールの出力を過信して、自分の臨床的判断よりAIの診断を優先してしまう。

7.6 コンセプトドリフト（Concept Drift）— 3種類

ドリフトの種類 特徴 具体例
急激なドリフト（Sudden） 一度に大きく変化 COVID-19 パンデミックによる医療データの急変
漸進的なドリフト（Gradual） ゆっくりと変化 消費者嗜好の年単位での変化
繰り返しドリフト（Recurring） 季節変動など周期的 小売の購買パターンの季節変動
✅ 対策：本番データの定期モニタリング + ドリフト検出アルゴリズムの導入 + 定期的なモデル再トレーニング
Chapter 08 K3

AI固有の品質特性のテスト

学習目標： バイアステスト・テストオラクル問題・非決定論的AIへの対処法を説明できる。

8.1 自己学習システムのテストが難しい4つの理由

① 非決定論的動作
同じ入力でも結果が変わる可能性。従来の「期待値と比較」が難しい。
② 継続的な変化
モデルが学習を続けて動作が変わる。テストが「通った」状態が維持されない。
③ テストオラクル問題
「正しい答え」を定義することが困難。複雑な判断では人間でも答えが分かれる。
④ 説明可能性の欠如
なぜその結果を出したかが分からない。欠陥の原因特定が困難。

8.3 バイアス検出テストの実装例

class AIBiasTester: """AI モデルのバイアスを検出するテストクラス""" def test_demographic_parity(self, model, test_data): """ 人口統計的平等（Demographic Parity）のテスト： 80%ルール — グループ間の陽性予測率の差が20%以内か確認 """ positive_rate_by_group = {} for sample in test_data: group = sample["protected_attribute"] # 性別・年齢・人種等 pred = model.predict(sample["features"]) if group not in positive_rate_by_group: positive_rate_by_group[group] = {"pos": 0, "total": 0} positive_rate_by_group[group]["total"] += 1 if pred == 1: positive_rate_by_group[group]["pos"] += 1 rates = {g: d["pos"]/d["total"] for g, d in positive_rate_by_group.items()} disparity_ratio = min(rates.values()) / max(rates.values()) return { "rates": rates, "disparity_ratio": disparity_ratio, "passes_80pct_rule": disparity_ratio >= 0.8, "result": "✅ 公平" if disparity_ratio >= 0.8 else "❌ バイアス検出" }

8.7 テストオラクルの4種類

オラクルの種類 概要 特徴
専門家オラクル ドメイン専門家が正解を判断 高精度だが時間・コストが高い
アンサンブルオラクル 複数モデルの多数決を正解とする バック・ツー・バックテストの基礎

AIベースシステムのテスト手法と技法

9.5 メタモルフィックテスト（試験最頻出！）

💡 定義 — テストオラクル問題を解決する技法
通常のテスト：入力 → 期待値と比較（期待値が分からない場合は困る）
メタモルフィックテスト：入力の変換 → 出力の変換が「メタモルフィック関係（MR）」を満たすか確認

典型的なメタモルフィック関係（MR）の例

MRの種類 内容 適用例
同値MR 同義語に変換しても出力は変わらないはず 感情分析モデル
対称MR 入力を対称変換しても出力は変わらないはず 画像分類（水平反転）
変換不変MR 画像を回転/反転しても分類は変わらないはず 猫/犬の画像分類
加法的MR 入力を2倍にすると出力も2倍になるはず 線形回帰モデル
順序MR 入力Aが入力Bより大きければ出力Aも大きいはず 価格予測モデル
# メタモルフィックテストの実装例 import numpy as np def mt_image_classifier(model, base_image) -> dict: """ 画像分類モデルのメタモルフィックテスト MR1: 水平反転しても同じクラスに分類されるはず MR2: 明度±10%変化しても同じクラスに分類されるはず """ original = model.predict(base_image) results = {} # MR1: 水平反転（猫は反転しても猫のまま） flipped = np.fliplr(base_image) results["MR1_flip"] = { "passes": original == model.predict(flipped), "original": original, "flipped": model.predict(flipped) } # MR2: 明度変更（10%増加） brightened = np.clip(base_image * 1.1, 0, 255).astype(np.uint8) results["MR2_bright"] = { "passes": original == model.predict(brightened), "original": original, "brightened": model.predict(brightened) } return results # 感情分析モデルのメタモルフィックテスト（バイアス検出） def mt_sentiment_bias(model, text: str) -> dict: """MR: 性別代名詞を変更してもセンチメントは変わらないはず""" original_score = model.get_score(text) neutral_text = text.replace("彼は", "彼女は") neutral_score = model.get_score(neutral_text) diff = abs(original_score - neutral_score) return { "passes": diff < 0.05, # 5%以上の変化はバイアスの可能性 "diff": diff, "result": "✅ バイアスなし" if diff < 0.05 else "❌ バイアスの可能性" }

9.1 敵対的攻撃とデータポイズニング

攻撃の種類 定義 具体例 テスト上の意義
敵対的攻撃（推論時） AIを騙すために意図的に設計された入力 パンダ画像に微小ノイズ → テナガザルと誤分類 堅牢性（Robustness）のテスト
データポイズニング（学習時） トレーニングデータに悪意あるデータを混入 顔認識システムに誤ラベルデータを混入 EDAで外れ値として検出

9.3 バック・ツー・バックテスト vs A/Bテスト

バック・ツー・バックテスト

目的：2バージョンを同じ入力で実行し出力の差異を比較。テストオラクルがない場合・モデル更新時の回帰テストに有効。本番前に実施。

A/Bテスト

目的：2バージョンを実ユーザーに同時提供しKPIを比較。推薦アルゴリズムのテスト等に有効。本番環境で実施。統計的有意差を確認してから展開。

9.7 テスト技法の選択マトリクス

状況・目的 推奨技法
テストオラクルがない メタモルフィックテスト
新旧モデルの比較 バック・ツー・バックテスト
本番環境でのA/Bテスト A/Bテスト
バイアス・公平性の確認 バイアステスト（人口統計的平等等）
セキュリティ・堅牢性の確認 敵対的テスト
多数パラメータの組み合わせ ペアワイズテスト
予期しない動作の探索 探索的テスト + EDA

テストへのAI活用

学習目標： AIが有効・苦手なテスト活動を区別し、欠陥予測・テスト生成・回帰最適化を説明できる。

AIが得意なテスト活動 vs 苦手なテスト活動

✅ AIが特に有効なテスト活動

• 欠陥レポートの重複検出・分類（NLP活用）
• テストケース自動生成（要件→TC）
• 回帰テストの優先順位付け
• 欠陥予測（コードメトリクスから）
• UIの視覚的変化検出（Applitools等）

❌ AIが苦手なテスト活動

• 創造的な探索的テスト（経験・直感が必要）
• ユーザビリティテストの評価（主観・感覚が必要）
• 倫理的判断が必要なテスト設計
• 完全に新しい未知のシナリオのテスト

サンプル問題 Q1（K2 / Chapter 1）

問：「AI効果（AI Effect）」の定義として最も適切なものはどれか？

A) AIが人間の能力を超えること
B) AIが達成したことは「真のAI」ではないと思われる社会的現象
C) AIシステムが実世界に与える経済的影響
D) AIが従来型システムより高い性能を発揮すること

✅ 正解：B — チェスコンピューターが人間を倒した後「ブルートフォースなので真のAIではない」と言われた現象。AIの定義は社会の認識とともに変化する。

サンプル問題 Q2（K3 / Chapter 5 — 計算問題）

問：癌診断AI の結果：TP=80, TN=900, FP=20, FN=20。このモデルの再現率（Recall）は？

A) 80%　B) 88.9%　C) 90%　D) 96.1%

✅ 正解：A（80%）
再現率 = TP ÷ (TP + FN) = 80 ÷ (80 + 20) = 80 ÷ 100 = 80%
正解率 = (80+900)÷(80+900+20+20) ≈ 96.1%（D）とは別の指標

サンプル問題 Q3（K2 / Chapter 3）

問：顧客を購買パターンで自動的にグループ分けしたい。どのMLの形態が最も適切か？

A) 教師あり学習（分類）　B) 教師あり学習（回帰）　C) 教師なし学習（クラスタリング）　D) 強化学習

✅ 正解：C — 教師なし学習（クラスタリング）
グループ分けの「正解ラベル」がない場合はクラスタリング。教師あり学習はラベル付きデータが必要。

サンプル問題 Q4（K3 / Chapter 9 — 最頻出技法）

問：「このレストランは素晴らしい」と「このレストランは最高だ」（同義語に変換）は同じ感情スコアになるはずだという考えに基づいてテストを設計している。このテスト技法は何か？

A) A/Bテスト　B) バック・ツー・バックテスト　C) メタモルフィックテスト　D) 敵対的テスト

✅ 正解：C — メタモルフィックテスト
「同義語に変換しても感情スコアは変わらないはず」= メタモルフィック関係（MR）を利用してテストオラクル問題を解決。

サンプル問題 Q5（K2 / Chapter 7）

問：MLシステムの「コンセプトドリフト」に対処する最も適切なアプローチはどれか？

A) トレーニングデータの量を増やす　B) モデルをより複雑にする　C) 本番データを定期モニタリングして再トレーニングする　D) テストデータを増やす

✅ 正解：C
コンセプトドリフト = データの統計的特性が時間変化する現象。対処法は本番データの継続モニタリング + ドリフト検出 + 定期的な再トレーニング。
